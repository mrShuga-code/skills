# Прошивка контроллера колонны

ESP32-S3 DevKitC-1 N16R8 + три MAX31865 + экран ILI9341 2,8" с тачем FT6336,
активный зуммер 5 В и веб-страница в домашней сети. Логика — по документу
«Логика контроллера колонны», экраны — по макету.

## Файлы

| Файл | Что внутри | Когда трогать |
|---|---|---|
| `kolonna.ino` | запуск и главный цикл | почти никогда |
| **`config.h`** | пины, **экран** (инверсия, порядок цветов, поворот, частота), **тач** (поворот, отладка), **датчики** (PT100/PT1000, Rref, провода, калибровка по льду), зуммер, реле клапана, светодиод на плате, Wi-Fi-точка, часовой пояс, **лог перегонов** (`KEEP_LOGS`, `LOG_RUN1`) | если что-то работает не так |
| **`secrets.h`** | ваши сети Wi-Fi и пароль веб-настроек | один раз; в git не кладём |
| `secrets.example.h` | образец `secrets.h` без паролей | — |
| `lgfx_config.h` | полное описание экрана для LovyanGFX | обычно не трогать |
| `sensors.cpp` | опрос MAX31865, усреднение, фильтр скачков, неисправности | — |
| `logic.cpp` | перегоны, цвета, Тфикс, «Хвосты», стабилизация, охлаждение | — |
| `ui.cpp` | всё, что на экране, и обработка нажатий | — |
| `buzzer.cpp` | сигналы зуммера по приоритету | — |
| `relay.cpp` | реле электроклапана отбора (GPIO18): автоматика отбора (`logic.cpp`) и кнопка в вебе | — |
| `led.cpp` | RGB-светодиод на плате: цвет по сети и авариям | — |
| `history.cpp` | история для графиков, поминутный лог перегона с событиями и журнал Тфикс на flash, список прошлых перегонов для веба | — |
| `net.cpp`, `web.cpp`, `web_page.h` | Wi-Fi, время, прошивка по сети, веб-страница, калибровка по льду, файл калибровки | — |
| `settings.cpp` | настройки в памяти NVS | — |
| `fonts.h` | шрифты с кириллицей (сгенерированы, руками не править) | — |

Самые важные места в коде подписаны комментариями заглавными буквами:
`ИНВЕРСИЯ ЦВЕТОВ`, `ПОРЯДОК ЦВЕТОВ`, `ПОВОРОТ`, `ЕСЛИ НАЖАТИЕ СРАБАТЫВАЕТ НЕ ТАМ`,
`ТИП ДАТЧИКА И Rref`, `ЕСЛИ ДАТЧИК ПОКАЗЫВАЕТ ЕРУНДУ`.

## Что установить

1. **Arduino IDE 2.x**.
2. **Платы**: Boards Manager → `esp32 by Espressif Systems`, версия 3.x.
3. **Библиотека**: Library Manager → `LovyanGFX` (проверено на 1.2.x).
   Всё остальное (Wi-Fi, веб-сервер, OTA, LittleFS, NVS) уже входит в пакет esp32.

Папка скетча должна называться `kolonna`, все файлы лежат в ней рядом с `kolonna.ino`.

## Настройки Arduino IDE (меню Tools)

| Пункт | Значение |
|---|---|
| Board | ESP32S3 Dev Module |
| Flash Size | 16MB (128Mb) |
| PSRAM | **OPI PSRAM** (для N16R8 обязательно) |
| Partition Scheme | **8M with spiffs (3MB APP/1.5MB SPIFFS)** |
| Flash Mode | QIO 80MHz |
| USB CDC On Boot | Disabled, если кабель в порт **COM/UART**; Enabled, если в порт **USB** |
| Upload Speed | 921600 (если прошивка обрывается — 460800) |

`USB CDC On Boot` влияет только на монитор порта: если там пусто, переключите
этот пункт или переткните кабель во второй разъём платы.

## Первый запуск

1. Проверьте `secrets.h`: основная и запасная сети, пароль веб-настроек
   (`WEB_ADMIN_PASS`). Если файла нет — скопируйте `secrets.example.h` в `secrets.h`
   и впишите свои данные.
2. Прошейте и откройте монитор порта на **115200**. Там видно:
   - `[sens] датчик 1 (CS 4): модуль найден` — по каждому из трёх MAX31865;
   - `[ui] экран 320×240` — экран горизонтальный;
   - `[net] в сети «...», адрес http://192.168.x.x  или  http://kolonna.local`.
3. На экране выберите перегон. Адрес для браузера написан внизу экрана выбора.
   В левом верхнем углу всех экранов — имя сети Wi-Fi, к которой подключён
   контроллер (зелёная точка), или `Kolonna-setup` (жёлтая), если домашней сети нет.
4. В браузере: монитор открывается без пароля, «Настройки» — логин `admin`,
   пароль из `WEB_ADMIN_PASS` (заводской `123`; в вебе можно сменить, не короче 3 символов).
   Внизу главной страницы — блок «Прошлые перегоны» (скачать CSV без пароля), в «Настройках» —
   удаление перегонов и файл калибровки датчиков (см. ниже).

Значения из `config.h` и `secrets.h` применяются только при самом первом запуске
(и после сброса BOOT 10 с). Дальше пороги меняются в меню на экране, а тип
датчика, Rref, поправки, Wi-Fi и пароль — в вебе, без перепрошивки.

## Экран первого перегона (с 14.11.2026)

После первого перегона №30 на железе: сверху крупно **куб** (цифры 48 px, как царга во втором
перегоне), над числом скорость нагрева за 5 мин, внизу плитки плашка зоны и цветная шкала
20–100 °C. Под кубом — **царга** (синяя ниже порога, зелёная от порога) и **УО** (датчик 3,
«не участвует»). Графика куба на экране больше нет (и строки «График куба» в меню «Экран»;
графики остаются в вебе). Внизу две кнопки: **«Меню»** (пороги, экран, смена перегона) и
**«Конец перегона»** — спрашивает «Закончить первый перегон? Да / Нет», по «Да» последняя
минута пишется в лог («перегон окончен (с экрана)»), реле выключается, экран возвращается к
выбору перегона, «Продолжить» больше не предлагается. В вебе в первом перегоне под графиками
блок «Первый перегон» с кнопкой «Конец перегона» (с подтверждением), команда `/api/cmd?c=end`.

## Проверка экрана из меню

Меню → вкладка «Экран» (в обоих перегонах) → строка «Проверка экрана»:

- **«Цвета»** — четыре страницы, нажатие на экран листает: цветные полосы с «ВЕРХ»
  и уголками (`LCD_INVERT`, `LCD_RGB_ORDER`, поворот), 16 градаций серого
  (тёмные сливаются с серым, а не с чёрным — экран пересвечен), чёрное поле
  (светлеют края — это свет подсветки, уменьшите «Подсветку»), белое поле.
  После белого — обратно в меню.
- **«Тач»** — калибровка тача только вне перегона (с 13.11.2026): во время перегона
  строка «Тач: на экране выбора, BOOT 3 с». Калибруйте на экране выбора перегона кнопкой BOOT.

Во втором перегоне в меню три вкладки: «Царга», «Куб», «Экран».

## Кнопка BOOT (когда экран уже работает)

- **держать 3 с и отпустить** — калибровка тача: нажмите по очереди на стрелки в углах.
  Только на экране выбора перегона (с 13.11.2026); на время калибровки главный цикл снят
  со сторожевого таймера, перезапуска не будет, сколько бы она ни шла;
- **держать 10 с и отпустить** — сброс всех настроек к заводским и перезапуск.

Пока держите, на экране написано, что произойдёт. Не держите BOOT в момент
включения: ESP32 уйдёт в режим прошивки (отпустите и нажмите RST).

## Светодиод на плате

RGB-светодиод на самой ESP32-S3 показывает состояние, пока плата без корпуса:

| Светодиод | Что значит |
|---|---|
| зелёный горит | подключён к Wi-Fi, аварий нет, всё хорошо |
| синий мигает раз в секунду | ищет домашнюю сеть Wi-Fi |
| синий горит | поднята своя точка `Kolonna-setup`, адрес http://192.168.4.1 |
| красный часто мигает | авария: неисправен датчик («обрыв или КЗ», «нет модуля», «проверьте тип и Rref») или тревога «Хвосты». Авария важнее сети |

При неисправном датчике «Сброс тревоги» снимает звук, а светодиод мигает красным,
пока датчик не в норме. Яркость — `config.h` → `STATUS_LED_BRIGHT`.

## Реле клапана отбора (с 28.10.2026)

Заготовка под электроклапан: GPIO18 → 220 Ом → затвор P3055LD (10 кОм с затвора на GND),
в стоке катушка реле 5 В с диодом 1N4007, контакты реле на клеммник к клапану. Схема —
лист «Питание и клапан» в «Схема подключения.pdf».

Клапан 2V025-08, 12 В, нормально закрытый: реле включено = клапан открыт. С 13.11.2026
реле во втором перегоне переключает автоматика отбора (см. «Клапан отбора» ниже).
Блок «Реле клапана» на главной странице веба остался: кнопка «Включить» / «Выключить»
работает вручную до следующего решения автоматики (автоматика переключает реле только
когда меняется то, что она хочет). После включения питания и после перезагрузки реле
всегда выключено. Ручное переключение пишется в лог: «реле клапана включено (веб)».

## Клапан отбора (второй перегон, с 13.11.2026)

- **Режим отбора.** Нажатие на плитку «УЗЕЛ ОТБОРА» открывает окно: «Отбор голов»,
  «Отбор тела», «Отбор хвостов», «Закрыть отбор» / «Открыть отбор», «Конец перегона»,
  крестик — закрыть окно. В вебе под графиками блок «Режим отбора» с теми же кнопками.
  Выбор режима сразу открывает клапан (короткий сигнал, строка на 2 с). «Закрыть отбор»
  закрывает клапан, режим остаётся («ТЕЛО · ЗАКРЫТ»); «Открыть отбор» открывает снова.
  Второй перегон начинается с закрытым клапаном. После перезагрузки и «Продолжить» режим
  помнится, клапан закрыт — открывает оператор. Экран выбора перегона закрывает клапан,
  как и переход из второго в первый перегон или экстракцию любым путём (в том числе
  командой веба `run1` / `run3`). «Открыть отбор» и «Отбор тела» проверяют правила паузы
  до включения реле: если царга уже выше порога, клапан не открывается ни на миг.
  Фиксация Тфикс режим не меняет: тело выбирает оператор.
- **Плитка УО:** серая «ЗАКРЫТ» (режим не выбран) или «ТЕЛО · ЗАКРЫТ», «ГОЛ. · ЗАКРЫТ», «ХВ. · ЗАКРЫТ» (закрыт вручную),
  жёлтая «ГОЛОВЫ», зелёная «ТЕЛО», оранжевая «ХВОСТЫ», серая «ПАУЗА 0:12» (пауза на теле),
  красная «ЗАКРЫТ 3:12» (тревога «Хвосты»), «ЗАКРЫТ: ЦАРГА» (датчик царги неисправен).
  Неисправность датчика 3 видна поверх подписи, на клапан не влияет.
- **Головы:** клапан просто открыт, скорость — игольчатым краном.
- **Тело** (с действующей Тфикс): царга ≥ Тфикс + 0,07 дольше 5 с — пауза клапана;
  ≥ Тфикс + 0,08 (всегда дельта + 0,01) — пауза сразу. Короткий сигнал. Открывается, когда
  с начала паузы прошло 30 с и царга ниже Тфикс; если не ниже — проверка ещё через 30 с.
  Сравнение по сотым (как на экране), значения — среднее за 5 с. Тревога «Хвосты»
  (+0,10 дольше 3 с) держит клапан закрытым; после «Сброса тревоги» он открывается только
  по правилам паузы. Новая Тфикс снимает паузу. Датчик царги неисправен — клапан закрыт,
  пока датчик не вернётся. Без Тфикс клапан открыт, пауз нет. Тфикс из памяти после
  перезагрузки, пока не нажали «Подтвердить», держит клапан на теле закрытым
  («ЗАКРЫТ: ТФИКС»; с 13.11.2026).
- **Нет свежих данных с царги 15 с** (с 13.11.2026, `config.h` → `VALVE_STALE_MS`): на теле
  клапан закрыт, плитка «ЗАКРЫТ: ЦАРГА», в лог «нет свежих данных с царги 15 с, клапан закрыт».
  Данные пошли снова — «данные с царги снова свежие, клапан по правилам паузы». Тревога
  «Хвосты» и Тфикс по-прежнему считают данные устаревшими через 3 с.
- **Частые паузы:** 3 паузы за 10 мин (куб ниже 90 °C) или 5 за 10 мин (куб от 90 °C) —
  серия сигналов и надпись «Частые паузы клапана … уменьшите скорость отбора краном»
  на экране (вместо нижних кнопок, «Понятно» — нажатием) и в вебе. После надписи счёт
  пауз начинается заново.
- **Хвосты:** клапан открыт всегда, тревога «Хвосты» в этом режиме не считается. Куб дошёл
  до 98,0 °C — серия сигналов и «Куб 98,0 °C · перегон окончен, выключите нагрев»;
  нажатие (в вебе — кнопка с подтверждением) = «Конец перегона».
- **«Конец перегона»** (с 13.11.2026 и на экране сначала окно «Закончить второй перегон?
  Нет / Да, закончить», как в вебе): клапан закрыт, в лог «перегон окончен», последняя минута дописана,
  файл закрыт (виден в «Прошлых перегонах»), экран выбора перегона; «Продолжить» больше
  не предлагается, следующий второй перегон — новый файл.
- **Настройки** (веб → Настройки → «Клапан отбора»): дельта 0,07 (0,02–0,30), задержка 5 с
  (1–30), пауза не короче 30 с (10–120), частые паузы 3 за 10 мин, куб от 90 °C — 5 за
  10 мин, хвосты — перегон окончен при кубе 98,0 (90–100). Блок настроек прошлой прошивки
  читается как есть, новые поля берут заводские значения.
- **Лог:** выбор режима и ручное открытие/закрытие (с кубом), каждая пауза
  («пауза клапана №3: царга 78,50 (+0,08, сразу)»; Тфикс и куб — в своих колонках строки),
  её конец («пауза клапана окончена через 1 мин: царга 78,39 ниже Тфикс, клапан открыт»),
  «частые паузы: 3 за 10 мин …», «клапан закрыт тревогой Хвосты», «перегон окончен».

## Сторожевой таймер (с 13.11.2026)

Если прошивка зависла и минуту (`config.h` → `WDT_TIMEOUT_S 60`) не проходит главный цикл
или опрос датчиков, контроллер перезапускается сам. Реле при перезапуске отпускается —
клапан закрыт. Во время прошивки по сети таймер сбрасывается, обновление не прерывается.
`WDT_TIMEOUT_S 0` — выключить.

## Включение с перегоном в памяти, перезапуск (с 13.11.2026)

Если при включении в памяти есть перегон (первый, второй или экстракция; его не закончили
«Концом перегона»), на экране выбора сразу окно «До выключения шёл …», таймер и две кнопки:
- **«Продолжить»** — тот же перегон: таймер, Тфикс (её надо подтвердить), режим отбора и
  **тот же файл лога**, первым событием «продолжение после перезагрузки» и «контроллер
  перезапускался: <причина>»;
- **«Новый перегон»** — перегон из памяти забыт (его файл остаётся в «Прошлых перегонах»),
  дальше выберите плитку: перегон начнётся с нуля, в новом файле.

В вебе то же: полоса «До выключения шёл …» с кнопками «Продолжить» и «Новый перегон»
(`/api/cmd?c=fresh`). Клапан после включения закрыт всегда.

**Тревога «Перезапуск»** (серия сигналов сразу и каждые 30 с, в окне красная строка
«Перезапуск · отбор закрыт» и причина: «просадка напряжения питания», «сторожевой таймер
(прошивка зависла)», «сбой прошивки», «включение питания», «кнопка RESET» …; в вебе надпись
с кнопкой «Понятно»):
- второй перегон — при любом перезапуске;
- первый перегон — только после сбоя: сторожевой таймер, сбой прошивки, просадка питания.
  Обычное включение питания (например, на другой день) — без сигналов;
- экстракция — никогда.
Сигналы прекращаются после «Продолжить», «Новый перегон» или «Понятно» в вебе. Причина
видна и в мониторе порта при старте («Причина запуска: …»).

## Смена перегона на экране выбора (с 13.11.2026)

Если на экране выбора есть перегон, который можно продолжить, а нажата плитка другого,
сначала окно «Закончить <перегон>? Таймер … не продолжится, <другой> начнётся с нуля» с
кнопками «Нет» и «Да, закончить». «Нет» — обратно на экран выбора, прежний перегон можно
продолжить. «Да» — в лог прежнего перегона «перегон окончен: выбран …», новый с нуля.
В вебе то же окно подтверждения браузера.

## Датчики PT1000 (с 23.10.2026)

Основной вариант теперь **PT1000 с резистором Rref 4,3 кОм** на модуле MAX31865
(маркировка «432»). Это значения по умолчанию в `config.h`:
`SENSOR_DEFAULT_PT1000 true` и `SENSOR_RREF_PT1000 4300`.
PT100 с резистором «431» (430 Ом) остался запасным: его можно выбрать в вебе,
«Настройки» → «Датчики» → «Тип», у каждого датчика отдельно.

**Перевод старых настроек делается сам, один раз.** При первом включении
этой версии каждый датчик, у которого в памяти стоял PT100, переводится на PT1000:
Rref 4300, поправка 0, дата калибровки стирается (старая калибровка была для PT100
и к новым датчикам не подходит). Wi-Fi, пароль, пороги и Тфикс не трогаются.
В мониторе порта при этом строка `[cfg] PT1000: 3 датч. переведено с PT100 на PT1000…`.
После перевода отметка хранится в памяти (ключ NVS `pt1k`), и если потом
вручную выбрать в вебе PT100, прошивка его больше не переделает.

После перевода сделайте калибровку по льду: здесь же в вебе или кнопкой
«Калибровка нуля» в тестовой прошивке (`kolonna-test`), а её файл загрузите
сюда через «Загрузить калибровку» (см. «Файл калибровки»).

Исправлено в этой же версии: числа от −1 до 0 (например, −0,42 °C во льду)
показывались без минуса — на экране, в вебе и в CSV. Теперь минус на месте.

**На железе эта версия ещё не проверялась**, только в симуляторе на ПК.

## Калибровка по льду

У резистора Rref на модуле MAX31865 допуск до 1 %, а 1 % — это до 2,6 °C ошибки.
Калибровка подгоняет Rref в настройках под резистор, который реально стоит на модуле:

1. Стакан доверху колотого льда, немного холодной воды, перемешать. Датчик в середину,
   подождать 2–3 минуты.
2. Веб → «Настройки» → «Датчики» → «Калибровать по льду» у нужного датчика.
   10 секунд не трогайте датчик: под кнопкой убывает полоска.
3. Страница покажет, что было во льду, и новый Rref, например «Rref 4300,00 → 4325,20 Ом».
   «Сохранить» записывает сразу, поправка при этом обнуляется.

Калибровка откажется, если датчик показывает дальше ±3 °C от нуля (он не во льду
или в поле Rref не тот резистор), если показания за 10 с разошлись больше чем на 0,5 °C
(датчик ещё остывает или его трогали) или датчик не отвечал. Одиночные скачки-помехи
в среднее не попадают, как и в обычных показаниях. «Сбросить» возвращает Rref к номиналу
(4300 Ом для PT1000, 430 Ом для PT100) и обнуляет поправку. Время и пороги — `config.h` → `CAL_SECONDS`,
`CAL_MAX_DEV_C`, `CAL_MAX_SPREAD_C`.

**Все три сразу (с 04.11.2026).** Кнопка «Калибровать все три по льду» под описанием
калибровки делает то же для всех включённых датчиков одновременно (все три в одном
стакане), как «Калибровка нуля» тестовой прошивки: у каждого датчика своя полоска и
свой результат. «Сохранить годные (N)» записывает те, у кого получилось; у остальных
остаётся причина отказа, их Rref не меняется. «Отмена» забывает все результаты.
Расчёт, допуски и время замера те же, что у кнопки отдельного датчика.

### Хранение калибровки и резервная копия (с 04.11.2026)

Rref, поправка и дата калибровки хранятся в памяти NVS и используются при каждом
включении: повторно калибровать после перезагрузки или обновления прошивки не нужно.
Кроме блока настроек (ключ `cfg`, даты — `calat`) калибровка всех трёх датчиков лежит
отдельной записью с номером версии и контрольной суммой CRC32, в двух одинаковых
копиях: ключи `calib` (основная) и `calib2` (резервная). Запись обновляется при каждом
сохранении настроек, только если калибровка изменилась.

При включении:

- блок настроек цел — калибровка берётся из него (как раньше); если в записи другие
  значения (Rref меняли вручную в форме, или питание пропало между записями), запись
  догоняет блок;
- блок настроек пропал (новая версия настроек, испорчен) или у датчика в нём испорчены
  Rref/поправка — калибровка этого датчика берётся из записи; в мониторе порта
  «[cal] датчик N: калибровка восстановлена из записи калибровки»;
- пропала только дата (`calat`) — дата берётся из записи;
- основная копия испорчена — берётся резервная, основная переписывается; испорчены обе —
  калибровка из блока настроек, если блока тоже нет — заводской Rref 4300 и пустая дата;
- значения из записи не применяются, если тип датчика или число проводов уже другие
  или Rref вне допуска калибровки по льду (4250,2…4351,0 Ом для PT1000).

«Сброс настроек» (BOOT 10 с) по-прежнему стирает и калибровку, в том числе обе копии
записи. Файл калибровки остаётся главной копией на случай замены платы или сброса.

### Файл калибровки

Там же, в «Датчиках», две кнопки. **«Скачать калибровку»** отдаёт файл
`kolonna-kalibrovka_2026-10-14.json` (дата скачивания; без часов — `kolonna-kalibrovka.json`):
по каждому датчику номер, имя, «включён», тип (pt100/pt1000), Rref, поправка, провода
и дата калибровки по льду. Паролей в файле нет. Сохраните его на телефоне или ПК:
после перепрошивки, сброса настроек или замены контроллера калибровку не придётся
делать заново.

**«Загрузить калибровку»** — выбрать файл; страница покажет таблицу «было → станет»
по датчикам, и только «Записать» меняет Rref и поправку (сразу в память, как «Сохранить»
настроек). Тип датчика, провода и «включён» из файла не записываются. Датчик из файла
не загружается, и причина пишется в таблице, если:

- тип датчика или число проводов в файле не те, что стоят сейчас (калибровка относится
  к паре «датчик + модуль»: если датчики переставили местами, старая не подходит);
- Rref вне допуска калибровки по льду: ±3 °C от номинала в пересчёте на Rref
  (для 430 Ом это 425,0…435,1, для 4300 — 4250,2…4351,0);
- поправка больше ±10 °C.

Если ни один датчик не подходит, не записывается ничего. Дата калибровки ставится при
«Сохранить» в калибровке по льду и при загрузке файла (берётся из файла), «Сбросить» её
стирает; видна в файле и в строке «сейчас: …» у датчика. Хранится она отдельно от блока
настроек (ключ NVS `calat`), поэтому старые настройки при обновлении не теряются.
Сделайте файл сразу после калибровки по льду: это и есть её резервная копия.

Такой же файл делает тестовая прошивка `kolonna-test` (кнопка «Скачать калибровку»
на её странице): номера датчиков те же (1 куб, 2 царга, 3 узел отбора), поэтому
откалибровать можно там, а загрузить сюда.

## Тфикс (второй перегон)

Тфикс — точка отсчёта для цвета царги и тревоги «Хвосты». Пороги и цвета прежние:
зелёный до +0,05, жёлтый +0,06…0,10, красный выше +0,10 дольше 3 с.

- **Зафиксировать с экрана**: кнопка «Зафиксировать Тфикс» → окно с живой температурой
  царги → «Зафиксировать». Записывается температура в момент нажатия «Зафиксировать»
  (среднее за 5 с, до 0,01). После фиксации — строка «Тфикс зафиксирована: …» и один
  короткий сигнал. «Отмена» ничего не меняет.
- **Из браузера**: на главной странице блок «Тфикс» с кнопками «Зафиксировать Тфикс»
  и (после перезагрузки) «Подтвердить». Пароля у этих кнопок нет, как и у остальных
  кнопок главной. Значение берёт контроллер, страница показывает его ответ.
  Сбросить Тфикс из браузера нельзя, только на экране.
- **Нельзя зафиксировать**, если датчик царги не в норме или данные не обновлялись
  дольше 3 с (`FIX_STALE_MS` в `config.h`). Тогда причина видна в окне и в вебе, старая
  Тфикс остаётся, отказ пишется в журнал. Пока данных нет, плитка серая «ДАТЧИК», Тфикс хранится, «Хвосты»
  на паузе; данные вернулись — всё продолжается само.
- **После стабилизации Тфикс сама не ставится.** Когда царга 5 минут (окно стабилизации)
  держится в коридоре 0,05, контроллер даёт 2 коротких сигнала и окно
  «Стабильно 5 мин · зафиксируйте Тфикс». «Позже» — напомнит раз в минуту, плитка остаётся
  сине-фиолетовой. Если царга вышла из коридора, запрос снимается и счёт начинается заново.
  Не дожидаясь, можно нажать «Зафиксировать» в любой момент после сброса тревоги.
- **«Царга вернулась к Тфикс».** В окне «Зафиксировать?» (и после стабилизации, и по кнопке,
  когда старая Тфикс есть) строка «было 75,30, сейчас 75,31 (+0,01)»: видно, вернулась ли
  царга после «Хвостов» к прежней Тфикс. Старая Тфикс остаётся, новую фиксировать не обязательно
  («Позже»). В лог перегона пишется, через сколько после «Хвостов» царга впервые снова вошла
  в зелёную зону старой Тфикс (до +0,05): «царга вернулась к Тфикс 75,30 через 4 мин после
  Хвостов», один раз на тревогу. То же в вебе: в баннере «Царга стабильна…» и в вопросе
  перед фиксацией.
- **Сбросить Тфикс**: меню → «Царга» → «Сбросить Тфикс», с подтверждением.
  На главном экране отдельной кнопки нет.
- **После перезагрузки** выберите тот же второй перегон: Тфикс вернётся из памяти,
  но плитка будет белой «ПОДТВЕРДИТЕ» и откроется окно «Тфикс из памяти» с кнопками
  «Подтвердить», «Заново» (от текущей температуры) и «Сбросить». Пока не выбрали,
  «Хвосты» не отслеживаются. Окно закрывается крестиком, нажатие на плитку открывает его снова.
  Если окно перекрыла тревога «Включите охлаждение», оно откроется снова после неё.
- **Журнал**: каждое действие с Тфикс (фиксация, сброс, подтверждение, отказ, восстановление,
  испорченная запись в памяти) — в мониторе порта, в вебе под блоком «Тфикс» (последние 20),
  в колонке «событие» CSV перегона и в файле `/log/N.ev` рядом с ним.
- Запись перегона в памяти NVS теперь с версией и контрольной суммой. Запись от прошлой
  прошивки читается, идущий перегон после обновления не теряется. Испорченная запись не
  восстанавливается: перегон начинается с нуля, в журнале «запись испорчена».

## Помощь на теле (второй перегон)

- **Режим отбора на плитке «УЗЕЛ ОТБОРА»** — см. «Клапан отбора» (с 13.11.2026 вместо отметок).
- **«Пар в узле отбора».** На разгоне второго перегона (пока Тфикс в этом перегоне не было),
  когда датчик 3 впервые поднялся выше порога (заводское 50 °C; меню → «Куб» → «Пар в узле
  отбора» или веб → Настройки → «Царга (второй перегон)», 30–90), — серия из 4 коротких
  сигналов и надпись «Пар в узле отбора. Приступите к стабилизации колонны» на экране
  (вместо нижних кнопок) и в вебе (баннер). Убирается нажатием «Понятно» на экране или в вебе,
  либо сама при фиксации Тфикс. Один раз за перегон; событие в лог: «пар в узле отбора:
  датчик 3 50,2, куб 78,1». Если в этот момент горит «Включите охлаждение», оно важнее:
  надпись и сигнал «пар» появятся после «Охлаждение включено». После перезагрузки и
  «Продолжить», если датчик 3 уже выше порога, сигнал не повторяется; при Тфикс из памяти
  он молчит, пока её не сбросят («Сбросить» + новая партия — сигнал будет), «Подтвердить»
  гасит его совсем. В первом перегоне сигнала нет. Порог подправить по первому логу (план развития).
- **Блок настроек в памяти** от этого расширился (порог «пар»): блок прошлой прошивки
  читается как есть, новое поле берёт 50 °C, Wi-Fi и остальное не сбрасываются.

## Экстракция (экстрактор Сокслета, с 13.11.2026)

Третий режим на экране выбора: полоса **«Экстракция»** под плитками перегонов (в вебе —
третья кнопка «Экстракция»). На экране только **температура куба крупно** (датчик 1, °C,
одна десятая) и внизу **«ВРЕМЯ РАБОТЫ»** с начала экстракции. В вебе — карточка «Куб · датчик 1»
и время работы в шапке, без графиков.

- Нет цветных зон, сигнала «Включите охлаждение», зуммера и тревог (при обрыве датчика
  вместо числа «——» и причина), клапан в этом режиме закрыт (реле вручную из веба работает как раньше).
- **Лог не пишется** (решение Artem 13.11.2026), в «Прошлых перегонах» экстракции нет.
- Меню — одна вкладка «Экран»: таймер (держать 1 с — обнулить), подсветка, проверка экрана,
  «Сменить перегон».
- Таймер, как у перегонов: «Назад к экстракции» или после включения «Продолжить» в окне —
  время идёт дальше; после другого перегона экстракция начинается с нуля. Тревоги
  «Перезапуск» в экстракции нет.
- Команда веба: `/api/cmd?c=run3`, в `/api/state` — `"run":3`.

## Полоска на графиках в вебе (с 14.11.2026)

На каждом графике веба (Куб, Царга, Узел отбора) своя красная вертикальная полоска.
Щелчок мышью или касание пальцем ставит её, дальше её можно тянуть мышью или вести пальцем
вбок (если вести пальцем вверх-вниз, страница прокручивается, полоска не ставится).
Справа вверху графика: время по часам телефона/компьютера и температура в этой точке,
например «14:32:10 · 78,45 °C» (царга с двумя знаками, куб и узел отбора с одним; обрыв
датчика — «нет данных»), кнопка «×» убирает полоску. После отпускания полоска стоит на
выбранном моменте и уезжает влево вместе с графиком; ушла за левый край — пропадает.
При смене периода (30 мин / 2 часа / вся перегонка) остаётся, если момент попадает в период.
Только веб (`web_page.h`), прошивка контроллера и API не менялись.

## Лог перегонов (CSV)

Лог пишется **в обоих перегонах** (с 13.11.2026, `config.h` → `LOG_RUN1 1`): по первому
видно разгон и полку куба на полной мощности. Если куб грузится в два захода, каждый заход —
отдельный перегон и отдельный файл. Писать только второй — `LOG_RUN1 0`. На flash хранятся **последние 10 перегонов** (`KEEP_LOGS`, с 14.11.2026; было 5),
лишние удаляются сами, когда начинается новый: **сначала короткие** (меньше минуты,
`LOG_SHORT_MIN`, от старого к новому), и только если коротких нет — самый старый. Кроме того
(с 13.11.2026), если при старте нового перегона во flash свободно меньше 200 КБ (`LOG_MIN_FREE`),
логи удаляются в том же порядке, пока места не станет больше (в лог нового перегона «мало
места во flash: удалено старых логов N»). Свободное место видно в вебе под списком «Прошлые перегоны».
После «Обнулить таймер» подробные строки по 5 с пишутся сразу, а «перегон окончен» попадает
в строку всегда, даже когда в минуте много событий (обычным событиям — до 640 байт).

Файл открывается в Excel (разделитель «;», десятичная запятая):

```
Второй перегон №19;начало 14.10.2026 09:30:00
минута;время;куб;царга;датчик 3;Тфикс;событие
0;09:30;21,79;21,48;21,31;;09:30:00 старт перегона, куб 21,8
34;10:04;54,93;22,86;22,33;;10:04:33 куб 55,0: включите охлаждение, разгон 34 мин
95;11:05;84,10;75,32;74,80;75,30;11:05:20 фиксация Тфикс 75,30 (с экрана)
157;12:07;88,60;75,38;75,10;75,30;12:07:08 царга выше нормы 75,37 (+0,07), жёлтая зона | 12:07:41 Хвосты: царга 75,42 при Тфикс 75,30 (+0,12)
```

- **«время»** — начало этой минуты, **«Тфикс»** — какая действовала в эту минуту (пусто — не
  зафиксирована), **«событие»** — все события минуты через « | » с точным временем.
  Без часов (нет интернета и веб не открывали) в первой строке «дата неизвестна»,
  «время» пустое, у событий «таймер 0:41:07» — от начала перегона.
- События: старт перегона или продолжение после перезагрузки (с кубом), «включите
  охлаждение» (куб и длительность разгона), «охлаждение включено» (с экрана или из веба
  и через сколько), каждая фиксация Тфикс («75,30 → 75,33»), сброс, отказ с причиной,
  подтверждение из памяти, жёлтая зона (не чаще раза в минуту), «Хвосты» (царга, Тфикс и
  превышение), сброс тревоги и стабилизация, «стабильно 5 мин, просит зафиксировать»,
  выход царги из коридора, неисправность датчика и возврат в норму (по каждому датчику
  не чаще раза в минуту), выход на экран выбора, сброс таймера, режим отбора и клапан (паузы, их длительность,
  частые паузы, конец перегона — см. «Клапан отбора»), «царга вернулась к Тфикс … через … после Хвостов»,
  «пар в узле отбора: датчик 3 …, куб …» (см. «Помощь на теле»).
  В строке минуты не больше 640 байт обычных событий (остаток до 800 байт держится для «перегон окончен»), дальше «…» (всё видно в мониторе порта).
  События, кроме Тфикс, в веб-таблицу Тфикс не попадают.
- **Веб, главная страница, блок «Прошлые перегоны»** (виден и на выборе перегона, и во время
  перегона, без пароля): «Второй перегон №18 от 14.10.2026 12:37 · 36 мин · 1 КБ · Скачать»
  (первый — «Первый перегон №17 от …»), новые сверху,
  текущий с пометкой «идёт» — его тоже можно скачать в любой момент. Файл скачивается
  латиницей, с видом перегона, номером и датой (с 13.11.2026): `vtoroj-peregon-18_2026-10-14_12-37.csv`,
  `pervyj-peregon-17_2026-10-14_09-05.csv` (без даты — `vtoroj-peregon-18.csv`). До 13.11.2026 было `kolonna-18_….csv`.
- **Удалить** — веб → Настройки (под паролем) → «Перегоны на контроллере», с подтверждением.
  Текущий перегон и перегон с самым большим номером удалить нельзя: «Продолжить» после
  перезагрузки допишет его.
- Старые файлы на 5 колонок (прошивка до 14.10.2026, первая строка «Перегон 2») видны
  в списке с «дата неизвестна» и скачиваются как есть. «Продолжить» после обновления
  прошивки в такой файл не дописывает: перегон идёт в новый файл на 7 колонок.
- **После обновления прошивки** при первом новом втором перегоне старые файлы сверх 5
  удалятся разом (раньше хранилось 10). Нужные скачайте до этого.
- **Подробные строки раз в 5 с** (с 13.11.2026, один файл): на теле с Тфикс и открытым
  режимом отбора, как только царга поднялась до Тфикс + дельта (0,07) или идёт пауза клапана,
  в файл между строками минут идут строки каждые 5 с, пока пауза не кончится и клапан не
  откроется; затем снова поминутно. Перед ними — 1 мин до подъёма (каждые 5 с, из памяти).
  Колонки те же, «время» с секундами, в «событии» — «клапан открыт», «клапан закрыт» или
  «до подъёма» (без часов — «таймер 1:02:35 клапан закрыт»). Строки идут по времени: строка
  минуты, потом её 5-секундные строки. Для графика в Excel сортировать не нужно.
  `config.h` → `LOG_DETAIL_SEC 5`, `LOG_DETAIL_BEFORE 60`.

```
95;11:05;84,10;75,32;74,80;75,30;11:05:20 фиксация Тфикс 75,30 (с экрана)
156;12:06;88,55;75,33;75,08;75,30;
156;12:06:10;88,55;75,33;75,08;75,30;до подъёма
156;12:06:15;88,56;75,34;75,09;75,30;до подъёма
157;12:07;88,60;75,38;75,10;75,30;12:07:10 пауза клапана №1: царга 75,38 (+0,08, сразу)
157;12:07:10;88,60;75,38;75,10;75,30;клапан закрыт
157;12:07:15;88,60;75,36;75,10;75,30;клапан закрыт
```

- События минуты пишутся во flash вместе с её строкой, раз в минуту; при пропадании питания
  теряется только последняя неполная минута (как и раньше).

## Чем прошивка отличается от документа

- **Веб опрашивает контроллер раз в секунду** (`/api/state`), а не через WebSocket.
  Для глаза разницы нет, а лишняя библиотека не нужна.
- **Страницы зашиты в прошивку** (`web_page.h`), а не лежат в LittleFS: не нужно
  отдельно заливать файлы. LittleFS хранит только поминутные логи (5 последних вторых перегонов).
- **Таймер идёт с выбора перегона.** После перезагрузки выберите тот же перегон —
  продолжатся таймер, Тфикс (с подтверждением, см. «Тфикс») и состояние охлаждения.
  Другой перегон начинается с нуля.
- **Новую Тфикс после стабилизации ставит оператор** (по запросу контроллера), а не
  прошивка сама из среднего за минуту, как было в документе.
- **Новое состояние датчика «проверьте тип и Rref»**, чтобы ошибка настройки
  не выглядела как обрыв.
- Пока **нет** имён каналов, тайм-аута подсветки и имени устройства в вебе
  (имя для `kolonna.local` задаётся в `config.h` → `NET_HOSTNAME`).

## Шрифты

`fonts.h` создаёт скрипт `tools/make_fonts.py` из свободных шрифтов DejaVu.
Чтобы добавить символ или поменять размер, поправьте список в скрипте и запустите:

```
python3 tools/make_fonts.py /usr/share/fonts/truetype/dejavu kolonna/fonts.h
```

Нужен Python 3 с пакетом Pillow.
